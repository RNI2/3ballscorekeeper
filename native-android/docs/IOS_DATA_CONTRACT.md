# Platform-neutral game record contract, version 1

This contract is independent of Android, Room, Kotlin class names, and any future backend. An iOS implementation can use Swift Codable value types and its own local store. JSON Schema: `contract/game-record-v1.schema.json`. Shared, independently authored examples: `../records/src/test/resources/contract/active-v1.json` `completed-v1.json`, and `master-completed-v1.json` (negative-score tie). Kotlin tests decode and round-trip all three fixtures; they are not generated by the Kotlin serializer.

## Encoding and versions

UTF-8 JSON, camelCase keys, explicit nulls, uppercase enum strings, signed integers. Timestamps are UTC Unix epoch **milliseconds**, not locale strings or seconds. Scores are signed, including negative Master scores. Round indices are zero-based; `withdrawnRound` is deliberately one-based to match scoring eligibility rules. A null turn means no saved score; a zero score is a valid saved turn.

`storageSchemaVersion: 1` versions this document; `rulesetVersion: "three-ball-2026.1"` versions scoring semantics. These are separate from Android's Room database version (currently 2). Both record version keys must be present. Reject unsupported versions, statuses, rule names, and action types without rewriting the original data. Readers ignore unknown additive object fields. Writers emit every property shown in the schema, including defaults and nulls. Property order and whitespace have no meaning. JSON Schema checks structure; the replay and consistency rules below are also mandatory.

## Identity and configuration

- `gameId`, participant `playerId`, and every `eventId` are canonical lowercase UUID strings. Generate a new event ID per accepted action. Player IDs remain unchanged through rename, correction, withdrawal, serialization, and restoration. IDs are never derived from display names.
- `players` is the immutable starting roster in turn order. `displayName` is the starting name. Rename events produce the current display name; `result.players` freezes final names. Repeated names do not imply the same person. This release creates new local roster identities when starting a new game; it does not merge people across games by name.
- Optional `accountId` and `regionId` are nullable metadata. Local writers emit null. A local player UUID is **not** an authenticated account ID and must never establish online identity or competitive eligibility.
- `configuration` contains difficulty, scratch placement, effective shot cap, and optional round limit. Novice cap is null, Expert cap is 5, Pro requires 1–99, Master requires 1–99 (setup default 6). Only Master may have a round limit (1–999 or null). Player limits are 2–6 except Master, 2–20.
- `startedAtEpochMillis` is assigned once. New event time is max(current clock, previous event time/start time), so a clock rollback does not reorder the log. Timestamps are local observations, not trusted competition timing.

## Event replay

`events` is the complete ordered audit log, including undone hits, scratched hits, corrections, withdrawn players, and discarded unfinished drafts. Start from the configuration and starting roster. Replay every action through the ruleset. No Firebase event/service semantics are implied.

Each event has a unique `eventId`, contiguous `sequence` starting at 1, nondecreasing `occurredAtEpochMillis`, and the **pre-action** `roundIndex` and `actorPlayerId` (current player). The actor is a scoring slot, not an authenticated user. Validate that this position matches replay state before executing the action. Targets use stable player IDs from the starting roster.

| Action `type` | Parameters and behavior |
| --- | --- |
| `HIT` | `balls` required: 0 in standard modes; 0 through remaining balls in Master. Count one physical hit. |
| `SCRATCH` | Standard scratch counter +1, or attach one scratch to the latest Master hit. |
| `UNDO` | Undo a physical hit; standard scratches remain, Master removes the hit's attached scratch and balls. |
| `UNDO_SCRATCH` | Native correction for an accidental standard scratch: decrement scratch count and clear the final-scratch latch. Master rejects this; use per-hit undo. |
| `DONE` | Save eligible draft and advance, or return to the pre-correction destination. |
| `BACK` | Previous active turn, with `discardDraft` explicitly true if discarding a dirty draft. |
| `REOPEN` | Master correction; `targetPlayerId` and zero-based `targetRound` required. `discardDraft` confirms a dirty draft discard. |
| `RENAME` | `targetPlayerId` and `name` required. Engine trims whitespace and uses Player N for blank names. |
| `WITHDRAW` | `targetPlayerId` required; preserve scores, mark 1-based withdrawal round, exclude from winners. |
| `FINISH` | Terminal event. Discard unsaved draft; no later event is valid. |

All other parameters are null; `discardDraft` is false except BACK/REOPEN. Unknown parameters may be retained by a future reader, but known parameters must not be used with the wrong action type. The detailed standard/Master rules, cap and scratch behavior, Back-from-review behavior, and withdrawal eligibility are specified in `SCORING_RULES.md`. During a Master correction, Finish and withdrawal are blocked.

Standard `UNDO_SCRATCH` is an additive native correction command. It does not change the original scoring arithmetic or the existing 16 JavaScript comparison scenarios. An iOS implementation of this version must support it.

## Status and immutable completion

- `ACTIVE`: no completion timestamp or result. Replay may be in live play, final-round review, or an open Master correction. Derive those states by replay; review alone does not finish a game.
- `COMPLETED`: terminal FINISH event, completion timestamp equals the last event time, and at least one complete round. `result` is required and immutable.
- `DISCARDED`: FINISH with no complete rounds, result null. Android clears active state without adding a history record. Explicit Abandon clears the active record without creating any completed document.

`result` includes final player IDs/names/activity/withdrawal rounds/totals, winner IDs, tie flag, complete-round count, round-by-player turn matrix, and competitive metadata. Turns freeze physical hits, scratches, Master hit outcomes, remaining penalty, and score. Standard `hits` arrays are empty; their physical hits and corrections are preserved in `events`. Matrix columns always match the starting roster, including withdrawn players. A trailing empty round is permitted.

Recompute results from replay and compare **all** result fields; reject mismatches. Totals include saved partial rounds, exclude unsaved drafts, and retain withdrawn scores. Winners are active players with a saved score at the lowest total; more than one is a tie. Finish and archive/active-clear must be one local transaction. Repeated completion of the identical game must not create or overwrite an existing result.

## Casual records and future competition

This version writes `syncStatus: "DISABLED"`, `syncEligible: false`, and `competitive: {"category":"CASUAL","eligible":false,"reasons":["LOCAL_UNVERIFIED"]}`. It never uploads records. Account/region placeholders cannot change that policy. A future competitive submission must be a separate authenticated, consented, validated workflow and versioned record type; do not relabel or overwrite a casual snapshot as a verified competitive result.

This contract provides storage compatibility, not cryptographic authenticity or an anti-cheat guarantee. The event/result consistency checks detect malformed and inconsistent records, not a deliberately rewritten internally consistent local history.
